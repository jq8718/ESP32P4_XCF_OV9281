## 工作分配

优化前 Core 0 在每个 CSI 帧上执行完整定位标记搜索，Core 1 做归一化、DataMatrix 内容解码、角点精修和姿态计算。
现场无图片上传时，前端搜索单帧约 18.7 ms，后端归一化、解码、角点精修约 7 ms。

现在在二值化之后交接一帧的搜索工作区：

- Core 0：CSI 取帧、6/4 像素网格采样、局部二值化，发布最新待处理帧。
- Core 1：相同网格上的连通域、候选标记几何判定、归一化、码字/纠错、角点精修、姿态计算与结果提交。
- JPEG 任务仍可在两核间调度；TinyUSB、UVC、CDC 和 UART 服务仍按现有配置运行。

对于第一轮 6 像素采样未找到标记的场景，Core 1 仍按原逻辑完成 4 像素密采样重试。
这保留原有失败处理路径，避免跨核来回交接。搜索工作区归属于帧槽：消费后释放，等待帧被新帧替换时也在该槽复用前释放。
没有使用上一帧 ROI、取消解码或更改图像上传协议。

## 现场同环境对照

板子通过 COM4 烧录，测量通过 CDC COM65；码位置、光照未改。
每组测量 12 s，发送 `@TIMINGON`、`@PROFILEON`、`@GEOMETRYON`、`@SUBPIXELON`，并计数串口输出。
`@CPU` 是每秒以两个 Idle Task 的运行时间算出的核心忙碌率，含 USB/ISP 等所有任务和系统开销；
`@PROFILE` 和 `@FRONT` 是选取的阶段耗时，不代表核利用率。现场逐行数据保存在本地 `build/core_balance/*.json`。

| 固件与传图 | Core 0 | Core 1 | 成功/总扫描 | 结果速率 | 前端交接之前 | 连通域+几何 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 优化前，关闭图片 | 98.5% | 49.3% | 603/603 | 50.3/s | 约 18.7 ms | Core 0，约 4.1 ms |
| 仅加诊断，关闭图片 | 98.6% | 49.8% | 602/602 | 50.2/s | 约 18.6 ms | Core 0，约 4.1 ms |
| 分段后，关闭图片 | **81.9%** | **66.6%** | **603/603** | **50.3/s** | 约 14.9 ms | Core 1，约 3.4 ms |
| 分段后，按需上传图片 | **84.0%** | **68.5%** | **571/571** | **47.6/s** | 约 16.8 ms | Core 1，约 3.4 ms |

传图组发送 33 次 `@SNAP`，接收 33 张图像的帧头，实际约 1.74 MB 的 `@DATA` 文本。
图片上传使两核各增加约 2 个百分点，并令成功结果速率从 50.3 降到 47.6/s。
这与图像复制、JPEG 编码、CDC 传输及缓存竞争一致；关闭传图不会停止取帧和解码。

`@FRONT` 平均值：优化前采样 5.4 ms、二值化 9.8 ms、连通域 3.7 ms、候选几何 0.4 ms；
优化后关闭传图时采样 6.2 ms、二值化 8.6 ms、连通域 3.0 ms、候选几何 0.4 ms。
这些是非同帧的 1 Hz 采样均值，现场竞争和缓存状态会造成小幅变动。

## 正确性与限制

主机按同一帧对比原单段路径和新两段路径，10 张保存的成功/失败 Gray8 图在普通采样与强制 4 像素密采样下均一致：
解码状态、码内容、ROI、角点、精定位质量全部相同，共 20 组。脚本入口 `tools/dm_stage_trace.c` 的
`XCR_DM_PREPARED=1` 与 `XCR_DM_TWO_STAGE=1`。

固件使用 ESP-IDF 5.4、ESP32-P4 v1.x 工程配置编译通过，并已刷入 COM4 板。验收覆盖当前静态现场；
其他光照、转角、运动模糊下的实机成功率仍应继续观察。
若要追求更高帧率，下一步要减小全图采样和二值化本身的开销，而不是仅追求两核占用百分比接近。
