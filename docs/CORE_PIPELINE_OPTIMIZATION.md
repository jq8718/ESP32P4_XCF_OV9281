# 双核实时解码流水线优化（2026-11-10）

## 改动

- Core 0 仅负责 CSI/DMA 缓冲区取帧、灯光控制及 USB/CDC 任务；Core 1 连续执行 DataMatrix 解码、原图角点精修和结果提交。移除了 Core 1 → Core 0 的单槽精修队列，避免已解码结果在等待精修时被新结果替换。
- 实时取帧路径不再每帧读取曝光/增益，也不再做 8×8 间隔的应用层亮度均值采样和未生效的软件曝光建议。CSI/MMAP 缓冲、ISP/IPA AE 保持工作。非实时模式的曝光函数保留。
- 删除采集阶段的实时 UVC 帧预览提交。UVC 和 CDC 图片都来自处理完的解码帧；开启预览仍可显示成功/失败帧，关闭时无需编码视频帧。
- 详细算法日志由每帧打印改为每 50 帧打印，CDC 结果及可选 `@TIMING` 仍逐条发送。`agv_decode` 栈从 20480 增至 28672 字节，以容纳合并后的精修调用。

## 板端验证

固件用当前 IDF 5.4 构建配置完整编译，写入 COM57 的 ESP32-P4，flash hash 校验通过。刷机前的应用备份在 `build/baseline_app_before_core_refactor.bin`。最终日志为 `decode_stages/board_timing_final.log`，CDC 对照为 `decode_stages/upload_benchmark_optimized.json`。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 解码完成到精修开始的等待中位数 | 23.46 ms（313 帧） | 0.021 ms（32 条抽样日志） |
| 开始解码到结果完成的中位数 | 45.22 ms（313 帧） | 19.63 ms（32 条抽样日志） |
| 精修阶段结果替换 | 20 秒内增加 311 | 单槽精修队列已移除 |

最终版本的开图/关图交替测试每段 6 秒、另有 2 秒预热：

| 阶段 | 图片上传 | 结果数 | 结果/秒 | 图片数 | CDC 报告解码中位数 |
|---|---|---:|---:|---:|---:|
| 1 | 开 | 262 | 43.67 | 16 | 19.83 ms |
| 2 | 关 | 279 | 46.50 | 0 | 19.77 ms |
| 3 | 开 | 262 | 43.67 | 16 | 19.88 ms |
| 4 | 关 | 281 | 46.83 | 0 | 19.79 ms |

四段共收到 1084 条成功结果；所有收到的 `@TIMING` 对应成功帧，开图收到 32 张成功图片。板端抽样日志均为 `012345`、状态 `OK`，没有超时或重启；解码任务最小剩余栈为 9200 字节。当前场景固定放着同一个 DataMatrix，速度与稳定性结论针对该现场条件。刷机前后相机角度和 UI 负载不同，表中旧版与新版中位数是现场对照，不能把全部差值归因于单一改动。开图结果频率仍比关图低约 3 条/秒，图片传输仍有独立成本。

## 下一步并行化判断

2026-11-10 的 18 条板端阶段日志中位数：定位标记检测 13.595 ms，ROI 归一化 2.682 ms，码字解码 2.088 ms，角点精修 1.259 ms，合计约 19.8 ms。双核占用率见 [实测记录](cpu_usage_20261110.md)：图片关闭时 Core 0 约 13.3%，Core 1 约 100%；图片开启时 Core 0 约 21%，Core 1 约 99.6%。

同一帧的归一化依赖标记定位结果，码字解码依赖归一化图，角点精修依赖解码后的四角；把这些步骤顺序迁往 Core 0 会引入核间等待，不能直接缩短单帧延迟。后续已在 AGV 实时模式启用左右重叠分区的并行标记搜索；边界位置、扩大目标及无码样本的验证和板端对照见 [并行标记搜索](PARALLEL_MARKER_SEARCH.md)。Core 0 同时承担 CSI 和 USB，实际加速幅度需以板端数据判断，不能仅以空闲率推算。
