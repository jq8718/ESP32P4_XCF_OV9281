## 1. 双核工作分配更均衡

原来 Core 0 做完整标记搜索，Core 1 做后端解码，Core 0 接近满载。现在交接点提前到局部二值化之后：

- Core 0：CSI 取帧、全图网格采样、局部二值化，发布最新待处理帧。
- Core 1：连通域、候选标记几何、归一化、DataMatrix 解码、角点精修、姿态计算及结果提交。
- JPEG 仍可调度到两核，保留原 CDC/UVC/UART 服务配置。

为每个帧槽保存搜索工作区，消费或复用时释放。保留 6 像素采样未找到标记时的同帧 4 像素密采样重试；重试在 Core 1 完成。保留最新帧覆盖和帧龄限制，不使用上一帧位置 ROI。

同一静态码、相同光照，每组测量 12 秒：

| 状态 | Core 0 | Core 1 | 成功/总扫描 | 结果速率 |
| --- | ---: | ---: | ---: | ---: |
| 优化前，关闭传图 | 98.5% | 49.3% | 603/603 | 50.3 次/秒 |
| 优化后，关闭传图 | 81.9% | 66.6% | 603/603 | 50.3 次/秒 |
| 优化后，按需传图 | 84.0% | 68.5% | 571/571 | 47.6 次/秒 |

传图组收到 33 个图片帧头。结论是减小了 Core 0 的占用并保留约 50 次/秒的静态识码能力；不表示所有运动、遮挡及光照条件都达到该速度。增加 `@FRONT` 诊断消息，按 1 Hz 报告采样、二值化、连通域和候选几何阶段耗时，需先启用 `@PROFILEON`。CPU 占用率包含系统与通信任务，不能当作单独解码算法的占用率。

10 张已有成功/失败原始帧分别按普通与强制密采样回放，共 20 组，新旧路径的状态、内容、ROI、角点及质量一致。更多阶段数据见 [双核优化实测](../../CORE_BALANCE_20261117.md)。

## 2. CSI 停帧现场诊断与超时恢复保护

实机复现过运行中 `VIDIOC_DQBUF` 持续超时：首帧和 USB CDC 正常，随后相机连续 32 秒无帧且不自行恢复。

本版在超时日志中增加帧序号、驱动持有帧位图 `held`、流水线状态 `states` 和剩余 PSRAM。连续 5 秒无帧时输出错误并调用 `esp_restart()` 重启整机，重新初始化摄像头。这里是整机复位，USB 会暂时断开再枚举，主机可能需要重连。

间歇性停帧的最初诱因尚未确认；此次保护不是对 CSI 硬件或缓冲区根因已修复的结论。恢复分支尚未通过故障注入验证。加诊断后的三轮连续传图测试共 155 秒未再停帧；保护版烧录后 30 秒测试收到 1429 条取帧耗时记录和 81 个图片帧头，无取帧告警。详见 [CSI 排查记录](../../CSI_STALL_20261118.md)。

## 3. 新增固定过道方向偏移 along_track_m

原 `tx` 是码中心在相机光学 X 轴上的坐标。AGV 原地转向时相机坐标轴也旋转，因此 `tx` 随之变化，不能直接代表固定过道方向的平移。

用户确认旋转轴经过相机光心，相机相对旋转中心的前后左右平移均为 0。本版复用同一帧精修姿态中的旋转矩阵第一列 `r1` 与三维平移 `t_CQ`，计算：

```text
along_track_m = -dot(r1, t_CQ) / 1000
```

`t_CQ` 单位为 mm。假设码正立贴右墙，固定过道前进方向对应码面 `-X`；码在前方为正、后方为负。它是沿该固定方向的相对位置，车辆原地旋转后并不改用新的车头方向。若标签旋转贴装、在左墙或需要反向定义，需要调整坐标映射或符号。

只增加一次三维点积和米制换算，复用已有 PnP 结果，不新增图像搜索或姿态求解。原 `tx` 及其余七个姿态/距离参数含义保留。实际角点、标定和姿态角噪声仍会影响新距离。

编译实际 `scan_pose.c` 在主机上与 OpenCV 比较，共 806 组样本、0 项失败；其中包含固定光心、偏航 -20°/-10°/0°/10°/20° 的样本。原字段距离差阈值为 0.2 mm，新增投影距离阈值为 0.3 mm；新增距离最大差约 0.256 mm。该数值是两种算法对照差，不是现场绝对测距精度。主机耗时也不能替代 P4 实机耗时。

新固件已通过 COM4 烧录。COM19 在 12 秒采样内收到 642 条完整 18 字段结果；当时静态画面的 `along_track_m` 均值约 0.1673 m、标准差约 2.4 mm。实车绕光心旋转的物理测试仍需现场完成，软件模拟测试不等于完成该实车测试。

## 4. UART 协议及 STM32 接收端变化

GPIO41=TX、GPIO42=RX，921600 baud、8N1，ASCII CSV，每行 `CRLF`：

```text
内容,x0,y0,x1,y1,x2,y2,x3,y3,帧号,yaw_y,pitch_x,roll_z,range_m,optical_depth_m,distance_to_plane_m,tx,along_track_m\r\n
```

从 17 字段变为 18 字段；角点仍为像素坐标乘 10，角度单位为度，距离单位为米。姿态无效时末尾八个字段留空。STM32 如按固定字段数解析，必须同时更新。USB CDC 原定位 CSV 不因这个 UART 扩展而增加字段。详见根目录 [USB_PROTOCOL.md](../../../USB_PROTOCOL.md)。

## 构建、烧录与回退

摄像头 UI：`tools/ov9281_debugger/README.md` 与同目录 `requirements.txt`、`build.ps1`。AGV UI：`tools/stm32_uart_debugger/README.md`、`requirements.txt`、`build.ps1`。运行 UI 构建脚本会增加版本号；备份 EXE 是本表列出的既有版本。

固件使用本机 ESP-IDF 5.4 编译，芯片为 ESP32-P4 v1.3，工程支持 P4 v1.x。备份应用为 891888 字节。进入 `releases/20261118/firmware`，在 IDF 环境使用备份烧录参数：

```powershell
python -m esptool --chip esp32p4 -p COM4 -b 460800 --before default_reset --after hard_reset write_flash "@flash_args"
```

该命令写 bootloader、分区表和应用，不擦除 NVS 自定义标定。COM4 是本机烧录口，其他电脑需换成对应端口。

回退优化前版本可检出 `checkpoint/pre-core-balance-20261117` 并重新编译；该旧标签仅保存源码和旧产物哈希，不包含旧 EXE/固件本体。此发布标签包含上述两个 EXE 和当前固件本体。`manifest.json` 校验的是 Git 实际保存的文件内容，不含其自身；EXE 与固件按原始字节保存，源码文本在 Git 中可能已归一化为 LF，Windows 检出后自动转 CRLF 时应以 `git show HEAD:路径` 的原始字节校验。后续提交或重编译后，产物与源码对应关系应重新记录。
