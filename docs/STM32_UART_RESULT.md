# GPIO41/GPIO42 扫码结果串口

当前 ESP32-P4 v1.x 扫码固件使用 UART1：GPIO41 为 TX，GPIO42 为 RX，921600 baud、8 数据位、无校验、1 停止位、无流控。连接 STM32 时共地，P4 TX 接 STM32 RX，STM32 TX 接 P4 RX。使用 3.3 V 逻辑电平，不连接 RS-232 电平。

成功解码且四角精修通过时，串口发送一行：

```text
内容,x0_10,y0_10,x1_10,y1_10,x2_10,y2_10,x3_10,y3_10,帧号,yaw_y,pitch_x,roll_z,range_m,optical_depth_m,distance_to_plane_m,tx<CR><LF>
```

末尾姿态字段仅在角点精定位通过、内容首字节是 `0` 或 `1` 时提供：`0` 选择 30 mm 码体，`1` 选择 50 mm 码体。其他内容仍发送解码、坐标和帧号，最后 7 个字段为空。三个角度单位为度，保留 2 位小数；距离与 `tx` 单位为米，保留 3 位小数。`tx` 是带符号的相机 X 方向偏移，图像右侧为正。

`<CR><LF>` 是连续的 `0x0D 0x0A` 两个字节，不发送 NUL。STM32 接收端可按 LF 分行并去掉行尾 CR。所有坐标都是原始 1280×720 图像中的像素位置乘以 10 后四舍五入的十进制整数，单位 0.1 像素。例如 `x0_10=10741` 表示 `x0=1074.1` 像素。使用精修后的子像素坐标；若子像素数据不可用，则用整数像素坐标乘 10。角点顺序与 USB CDC 一致，见 [STM32 CDC 对接协议](STM32_CDC_PROTOCOL.md#44-坐标与角点顺序)。

示例：

```text
012345,10741,5673,7440,6085,6888,3361,9595,2230,1032,-0.15,1.24,0.32,0.642,0.631,0.598,0.120<CR><LF>
```

内容字段采用与 CDC 相同的 CSV 和反斜杠转义规则：逗号或双引号触发 CSV 引号，控制字节写为 `\xHH`，反斜杠写为 `\\`。因此接收端需要按 CSV 规则解析首字段，不能直接用 `strtok` 分割。串口仅发送有效结果，不逐帧发送失败信息；发送队列只保留最新一条，拥堵时允许跳帧。帧号是采集帧序号，可能跳号，设备重启后重置。

该 UART 输出与 HS USB CDC 并行，互不替代。GPIO41/42 串口不承载烧录日志或 UVC 图片。

## 相机标定配置

默认使用 `参考资料/ost(1).txt` 中 OV9281 的 1280×720 标定：

```text
fx=733.242515, fy=732.511533, cx=589.273600, cy=359.376026
k1=0.119448, k2=-0.223125, p1=0.000163, p2=-0.000596, k3=0.083362
```

通过 UART RX 读取或更新标定参数：

```text
@CAL,GET<CR><LF>
@CAL,SET,width,height,fx,fy,cx,cy,k1,k2,p1,p2,k3<CR><LF>
```

`GET` 返回 `@CAL,DATA,width,height,fx,fy,cx,cy,k1,k2,p1,p2,k3<CR><LF>`；成功的 `SET` 返回更新后的 `DATA`，失败返回 `@CAL,ERR,原因<CR><LF>`。`SET` 只接受 1280×720 和有限、范围合理的数值。有效参数写入 ESP32-P4 NVS Flash，重启后自动加载；参数校验或 Flash 写入失败时保留此前生效值。尚无自定义值时使用上方默认标定。
