# 2026-11-19 无码搜索长尾优化

## 问题与原因

基线为远程整机测试版 `773bd2e`，没有修改已发布的整机测试固件。

1. 当前帧的背景纹理会触发小码 L 边候选，导致局部插值与阈值重试。
2. 一轮码体搜索失败后，又从头对相同 2px 二值图执行最长 24 ms 搜索。现场码体阶段经常达到约 68.6 ms。
3. 外标记左右分区重叠；两侧失败后又全图重扫。Core 0 同时承担下一帧预处理，分区搜索还增加争用。
4. 外标记采样、二值化、连通域和组合搜索内部未检查帧截止时间，过期帧仍占用 Core 1，下一帧只能等待。

## 实现

- 小码候选增加四侧白边抽样。每侧 12 点至少 6 点为白，避免把较大码内部或背景文字当成独立小码。
- 候选最高分低于 90、普通检测器也未输出四边形时，跳过局部小码插值重试，仍执行原灰度外标记搜索。
- 取消失败后重复启动的整张 2px 图搜索。普通检测仍有 12 ms 子预算，局部补救仍受总共 44 ms 的码体阶段预算限制。
- 外标记使用一次全图 6px 搜索，失败后保留 4px 搜索。弱候选帧仅运行常规阈值窗口；有候选或后续解码失败时仍保留小窗口补救。
- 6px 阈值改为等价滑动窗口求和，洪泛队列采用 16 位索引，1280×720 下临时缓冲从 128400 字节降至 78966 字节。该项单独实测没有明显提速，主要收益是减少临时内存。
- 在采样、阈值、连通域和标记组合循环内检查本帧截止时间；超时释放缓冲并返回。检查有粒度，仍会有少量越界耗时，不是严格的实时截止保证。
- 修正回归脚本：基线 C 和 C++ 都来自 HEAD，避免 C++ 算法变化被混入基线而漏报退化。

每帧独立分析。没有沿用上一帧的角点、ROI、二值化算法、采样步长或成功搜索路径。保留 Core 0 预处理、Core 1 解码的流水线。

## 现场实测

OV9281 1280×720 Gray8、50 fps；CPU 360 MHz、PSRAM 200 MHz。每项稳定后记录约 10 秒。遮挡测试先后使用同一白纸场景；有码测试在用户恢复完整标签后进行。逐项原始日志与统计对应见 `measurements.json`。

| 场景 | 基线 | 优化版 |
|---|---:|---:|
| 无码平均处理延迟 | 110.86 ms | 91.05 ms |
| 无码 P95 | 117.11 ms | 100.24 ms |
| 无码本次最大值 | 162.60 ms | 108.60 ms |
| 无码处理次数 | 11.38 次/秒 | 14.60 次/秒 |
| 有码平均处理延迟（含失败） | 106.59 ms | 79.72 ms |
| 有码成功率 | 37/121，30.58% | 175/176，99.43% |
| 有码成功吞吐 | 3.69 帧/秒 | 17.50 帧/秒 |

无码平均延迟减少约 17.9%，本次最大值减少约 33.2%；并不表示所有无码场景都会得到相同收益。

`decode_us` 是本工程上报的处理延迟，包含前处理、核间等待与后段计算，不能等同于纯算法 CPU 时间。1 Hz 阶段采样中，无码码体阶段均值从约 68.66 ms 降到 25.78 ms；有码从约 68.55 ms 降到 29.46 ms。最终有码 Core 0 平均约 86.1%，Core 1 约 98.4%。

图片上传独立对照：10.015 秒成功 156 帧，约 15.58 帧/秒，收到 47 张图片，成功率 96.30%。该项使用最终整理前的相同搜索策略，6px 缓冲当时仍使用积分图。最终固件的再测因 COM65 被外部程序占用而未启动；不能把该项作为最终二进制的精确性能值。

本轮未通过自动装置记录物理遮挡移开的准确时刻，因此没有将稳态处理延迟冒充“无码→有码首帧响应”实测值。当前场景仍未达到 40 帧/秒。

## 回归与内存验证

- 最终历史变换回归：1185 项，基线与当前均为 1090 项精修成功，新增失败 0，负样本误识别 0。并非 1185 项全部成功。
- 附加原始与小码样本：59 张全部解码并精修成功。
- ASan/UBSan：59 张均成功，无内存或未定义行为报告。
- 超时路径：1/50/200/500/1000/2000/5000 微秒预算各 20 次，共 140 次；分配/释放计数平衡，当前分配字节归零，无泄漏报告。桌面超时预算仅验证退出路径，不能用作 P4 耗时。
- 正常 ESP-IDF 应用编译并通过 COM4 烧录，NVS 未擦除；没有保留测试回放应用。
