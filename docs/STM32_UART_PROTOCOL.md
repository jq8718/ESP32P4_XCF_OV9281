# P4 → STM32 UART 整数协议 v6

此协议用于 GPIO41 TX / GPIO42 RX，921600 baud、8N1，3.3 V TTL、共地。它独立于 USB CDC；相机调试器的 USB 协议不变。上电默认发送精简模式，模式只保存在 RAM，重启后回到精简模式。

## 为什么使用整数

STM32 不必解析小数字符串：角度乘 1000，以毫度传输；距离以毫米传输；角点坐标乘 10。保持整数即可做阈值判断和控制，需要显示时再除以比例。小数文本也能用 `strtof` 解析，但字段开销更大，还需要处理浮点格式、空字段和范围。本版以带类型、版本及 CRC16 的整数文本兼顾串口调试和 MCU 实现；50 Hz 结果无需增加二进制封包的复杂性。

例如：`-12345` 毫度 = `-12.345°`；`-125` mm = `-0.125 m`；角点 `6198` = `619.8 px`。这些是传输分辨率，不表示实际测量精度。UART 帧号范围为 0～999，测量值为 int32。

## 数值位宽与溢出

线上传输是十进制 ASCII 文本，不是固定 4 字节二进制；每个测量字段的逻辑类型是 int32。`range_mm`、`depth_mm`、`plane_mm`、`tx_mm`、`along_mm` 与三个角度毫度字段均为 32 位有符号整数，理论范围 −2,147,483,648 ~ +2,147,483,647（距离约 ±2147 km）。P4 发送前用 `scan_uart_scaled_i32()` 检查 NaN/Inf 与 int32 边界，越界、非有限值或无法安全取整的帧直接丢弃，不会回绕或截断；STM32 解析器逐数字累积前检查溢出（负数允许到 2147483648），超出同样整行拒绝且输出结构保持不变。

## C 与 F 模式

遥测帧以 `@SCAN,6,<mode>,` 开头。`6` 是协议版本，第 3 个字段 `mode` 决定后续布局：

| 模式字母 | 含义 | CRC 前字段数 | 上传内容 |
| --- | --- | --- | --- |
| `C` | Compact，精简模式（上电默认） | 9 | 帧号、姿态有效标志、解码内容、偏航角、垂墙距离、沿过道偏移 |
| `F` | Full，完整模式 | 22 | 帧号、姿态有效标志、解码内容、四个角点、三个角度和五个距离 |

STM32 示例用同一个 `p4_scan_parse_line()` 逐帧识别两种模式。解析后 `result.compact == 1` 表示 C，`result.compact == 0` 表示 F，无需在接收端预设模式。解析成功且 `pose_valid == 1` 时才读取姿态。

## 帧号回绕

两种模式均发送 `sequence = 采集帧号 % 1000`，`999` 的下一采集帧显示为 `0`。帧号用 1～3 位十进制字符表示，`0` 发送为 `0`。STM32 C 示例和 AGV 调试器逐帧解析，接受 `999 → 0`，拒绝小于 0 或大于 999 的帧号。

需要比较帧号时，可用 `(current + 1000 - previous) % 1000` 算短时间内的间隔，例如 `998 → 1` 的差值为 3。UART 上报由成功解码和传输队列决定，可能跳号，差值不能直接作为串口丢包数。按 50 fps 计算约 20 秒重复一次。通信超时按接收时间判断。设备重启或间隔超过一个周期时，仅凭帧号无法判断间隔。

## 模式命令

每条命令以 CR 或 CRLF 结束，无空格：

| 命令 | 作用 | 应答 |
| --- | --- | --- |
| `@OUT,COMPACT` | 精简整数上传 | `@OUT,DATA,COMPACT` |
| `@OUT,FULL` | 完整整数上传 | `@OUT,DATA,FULL` |
| `@OUT,GET` | 查询当前模式 | `@OUT,DATA,当前模式` |

本版本已移除旧浮点 CSV（原 LEGACY）；旧接收端应改用本页整数协议。未知模式返回 `@OUT,ERR,command`。UI 的“上传完整数据”默认不勾选，连接成功后发送 COMPACT，勾选发送 FULL。只有收到相符应答才显示“已确认”。数据行自带模式标识，即使切换边界仍可按每行类型解析；应答前已经发送的旧行可能仍在主机接收缓冲中。

v6 规定帧号范围为 0～999。STM32 端请同步更新为本页的 v6 示例解析器。

## 精简数据（C）

```text
@SCAN,6,C,sequence,valid,payload,yaw_mdeg,plane_mm,along_mm*HHHH\r\n
```

星号前共 9 个字段。以下实例如帧号 0、内容 `012345`、偏航 −7.690°、离墙 375 mm、沿过道偏移 −30 mm，行尾再加 CRLF：

```text
@SCAN,6,C,0,1,012345,-7690,375,-30*E08E
```

### 光轴深度与离墙距离

- `depth_mm`（`optical_depth_m`）：码中心位置向量在相机光轴上的投影，即 `t_z`；它使用随相机转动的轴。
- `plane_mm`（`distance_to_plane_m`）：相机光心到码平面的最短垂直距离。固件用码面法向 `r3` 计算 `-dot(r3,t)`，有效姿态下为正。

当标签平贴墙面时，3D 的相机离墙位置应使用 `plane_mm`。绕相机光心原地旋转，理想情况下它不变；光轴深度会随转向变化。例如相机原先正对码中心且离墙 500 mm，绕光心转 30° 后，光轴深度约 433 mm，垂墙距离仍为 500 mm。不能用光轴深度代替垂墙距离，也不能仅用偏航角从光轴深度推算通用墙距，码中心沿墙偏移也参与关系。

UI 在精简模式下直接将 `plane_mm` 转米并平滑后驱动 3D，底部“离墙”与墙边厘米数值使用同一数据；墙边仅显示例如 `19.1 cm`，不加名称前缀。此距离的起点是相机光心；如需车身外壳到墙的净空，还需车体几何与安装位置换算。

精简帧中 `plane_mm` 为索引 7，`along_mm` 为索引 8；`depth_mm` 只在完整帧中出现。

### 角点与沿过道方向

四角点顺序是解码器的码体身份 P0→P1→P2→P3，不按画面左右重新排序。坐标为 1280×720 原图位置，X 向右、Y 向下，乘 10 后以整数传输；是有效码体模块外边界，不含白边、外部定位标记。P4根据内容最左边一位选择边长：`0`→30 mm（3 cm），`1`→50 mm（5 cm），`2`→70 mm（7 cm）。例如 `012345` / `112345` / `212345` 对应上述三种尺寸；STM32须保留内容的前导零。尺寸由P4用于姿态和距离计算，UART C/F帧字段布局不变。

`along_mm` 为码中心相对相机光心沿固定过道前进方向的有符号距离，前方为正。假设码正立平贴右墙，车前进方向为码面 `-X`；P4 计算 `-dot(R_CQ[:,0],t_CQ)`（毫米）。它不使用随车旋转的相机 X 轴；用户已确认转轴经过相机光心，安装平移为零。改变墙侧或标签朝向时需重新确定前进方向。

## 完整数据（F）

```text
@SCAN,6,F,sequence,valid,payload,x0,y0,x1,y1,x2,y2,x3,y3,yaw_mdeg,pitch_mdeg,roll_mdeg,range_mm,depth_mm,plane_mm,tx_mm,along_mm*HHHH\r\n
```

星号前共 22 个字段，3 个角度与 5 个距离全部来自同一帧的 P4 姿态计算：

| 索引（从 0 开始） | 字段 | 类型与单位 |
| --- | --- | --- |
| 0/1/2 | `@SCAN` / `6` / `F` | 固定头 / 版本 / 完整模式 |
| 3 | sequence | 0～999，采集帧号取模 1000，可能跳号 |
| 4 | valid | 0 或 1，表示姿态是否有效 |
| 5 | payload | 原始 ASCII 数字字符串，无引号，保留前导零 |
| 6～13 | 四角点 P0→P3 | int32，原图像素 ×10，顺序不变 |
| 14～16 | yaw / pitch / roll | int32，度 ×1000 |
| 17 | range_mm | 相机光心到码中心直线距离，mm |
| 18 | depth_mm | 码中心沿光轴深度，mm |
| 19 | plane_mm | 相机光心到码平面垂直距离，mm |
| 20 | tx_mm | 码中心在相机 X 轴上的有符号偏移，mm |
| 21 | along_mm | 码中心沿固定过道方向的有符号偏移，mm |

示例（行尾再加 CRLF）：

```text
@SCAN,6,F,999,1,012345,5213,2873,5749,2943,5695,3469,5152,3407,-7690,-7210,6650,407,406,400,-24,-30*E379
```

两种模式的 `payload` 都允许 1～255 位 ASCII 数字 `0`～`9`。例如 `012345` 在线上就是这六个字符，首位 `0` 是单字节 `0x30`。内容按 `payload_length` 读取，不保证有 NUL 终止符，也不要转成整数，否则会丢掉前导零。P4 不通过该 UART 上报含非数字字符的码，接收端会拒绝非法内容字段。

只有成功解码且角点有效的结果进入 UART 队列。DataMatrix 仍需角点精修通过。若码内容首字符不是 `0`、`1`、`2` 等原因导致姿态无法计算，则 `valid=0`，本帧仍有内容、完整模式仍有角点，所有姿态整数填 0。STM32 必须先判断 `valid`，不能把无效姿态的 0 当作到位或对准。精简帧不上传角点、俯仰、横滚、光轴深度、码中心直线距离和相机 X 偏移 tx，不能把未上传值当作 0 测量值。

## CRC16 与拆包

`HHHH` 为 CRC-16/CCITT-FALSE 的 4 位十六进制数，参数为多项式 `0x1021`、初始值 `0xFFFF`、不反射、xorout=0。校验覆盖从 `@SCAN` 的 `@` 开始到最后一个数值的最后一个字符，**不包括星号、CRC 字符或 CRLF**。标准输入 `123456789` 的校验值为 `29B1`。

采用 UART DMA + IDLE 或环形缓冲，在主循环/通信任务中按 LF 拆行；一次 DMA 接收可能含多行或半行。先找 `@SCAN,`，检查行长和星号，再校验 CRC、字段数量、版本、整数范围、有效标志，然后提交新结果。CRC 或解析失败丢弃整行，不覆盖上一条有效控制结果；控制器还应按收到有效结果的时间设置失联超时。设备可能输出 `@CAL`、`@OUT` 命令应答，应独立分流处理。

最长行限制 1024 字节。工程附有可直接移植的纯 C 解析器 [p4_scan_protocol.h](../examples/stm32_uart/p4_scan_protocol.h) / [p4_scan_protocol.c](../examples/stm32_uart/p4_scan_protocol.c)：无动态分配、无浮点解析，检查 CRC、整数范围和内容字符，验证不通过时保持输出结构不变。`p4_scan_parse_line()` 返回 1=合法遥测帧，0=其他消息，-1=损坏或不合法。函数内部约需 1.4 KB 栈空间，建议在通信任务执行，不放在中断中。

```c
p4_scan_packet_t result;
int status = p4_scan_parse_line(line, line_length, &result);
if (status == 1 && result.pose_valid) {
    int32_t yaw_error_mdeg = result.yaw_mdeg;
    int32_t wall_distance_mm = result.plane_mm;
    int32_t forward_error_mm = result.along_mm;
    if (!result.compact) {
        int32_t optical_depth_mm = result.depth_mm;
        /* 角点及其他完整帧字段也只在此分支读取。 */
    }
}
```

## 相机内参读取与下载

此功能需要双向接线：USB-UART RX 接 P4 GPIO41；USB-UART TX 接 P4 GPIO42；共地。仅接收 TX 的旧接线可以看默认精简结果，但不能切换模式或下载内参。

```text
@CAL,GET\r\n
@CAL,SET,1280,720,fx,fy,cx,cy,k1,k2,p1,p2,k3\r\n
```

内参是低频配置，仍使用小数文本保存原标定精度。成功返回 `@CAL,DATA,1280,720,fx,fy,cx,cy,k1,k2,p1,p2,k3`；SET 的 DATA 应答在 NVS 写入与提交成功后发出。失败返回 `@CAL,ERR,原因`，有效旧值不被替换。分辨率必须为 1280×720，fx/fy 在 100～10000，主点在图像内，所有数值必须有限，畸变参数绝对值不大于 10。

命令应答不附遥测 CRC，UI 下载后会比较回读值；操作超时不会显示成功，应重新 GET 核对。UI 不会自动把默认内参写入设备；“填入工厂默认值”或“导入 JSON”仅修改编辑框，需显式点击“下载内参到 P4 Flash”。保存成功立即生效，重启后读取 NVS。模式开关不写 Flash。

内参 JSON 支持平铺的 `width,height,fx,fy,cx,cy,k1,k2,p1,p2,k3`，也兼容已有 `camera_matrix/dist_coeffs/image_size` 格式。码体 30/50/70 mm 由内容首字符 `0`/`1`/`2` 选择，不在此窗口修改。

## 尺寸映射的配套软件

P4固件、P4ScanOV9281Debugger v1.0.0004、STM32 demo统一使用 `0`→30 mm、`1`→50 mm、`2`→70 mm。调试器从当前帧解码内容选择本地姿态计算尺寸，旧标定JSON中的 `qr_size_mm` 不覆盖该规则；原v1.0.0003已另存备份。AGV_3D_Test直接显示P4上传的姿态与距离。

STM32 demo提供 `p4_scan_code_side_mm(result.payload, result.payload_length)`，返回30/50/70毫米，未知首位或空内容返回0。该函数可用于区分标签规格；P4上传的距离已经使用对应尺寸计算，STM32不应再次乘尺寸比例。demo源文件及README同时打包在 `examples/stm32_uart.7z`，支持C/F两种模式。
