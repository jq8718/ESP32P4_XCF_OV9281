# 2026-11-19 远程备份版本

当日后续的整机联调版本见[输出给整机测试20261119](whole-machine-test/README.md)。

本版本保存自上次远程提交 `3f7d372` 之后的代码、UI、失败图像、二值化研究及最终板端验证。实验文件按实际采集日期2026-11-18归档。

## 改进

- 码内容首位统一映射：`0`→30 mm、`1`→50 mm、`2`→70 mm。同步P4姿态计算、USB调试器、本地姿态计算、STM32 demo及协议文档；未知首位不输出有效米制姿态，数字内容保留前导零。
- 4像素细搜索保留常规窗口，增加小窗口补救，处理偏暗标签纸面与外部标记粘连；当前帧候选组合或解码失败后可尝试另一窗口。仅记忆搜索步长/窗口选择，没有引入上一帧位置ROI。
- 在6像素粗搜索中对细长异常连通域做受预算限制的局部整数Otsu重分割，使粘连定位标记有机会在粗搜索直接恢复。复用原队列和掩膜，增加512字节直方图栈空间；4像素不做此重分割。
- 归档Downloads/captures中的5张原始失败图和配套元数据，并保存均值、中值、方向背景及局部重分割的研究脚本、对照图和完整回放记录。中值或方向背景并未直接替换产品全图二值化。

## 验证与实际收益

- 最终局部重分割实际C代码1185组对照：成功用例退化0组、新增误解码0组；61组ASan/UBSan检查通过。
- 5张captures原图×36种采样相位，共180组均成功；其中173组在6像素粗搜索完成，旧版仅2组。人工相位平移不是独立现场照片，且旧版最终也能解出全部180组。
- 最终板端同条件20秒对照：关闭上传旧版27.31 ms、新版27.56 ms；开启解码帧图片上传旧版29.96 ms、新版30.03 ms；无码旧版54.73 ms、新版55.32 ms（约增加1.1%）。正常现场速度基本持平，没有证明整体帧率提升。
- 815组姿态计算验证通过；1000组跨语言UART报文及CRC破坏、C/F模式、整数边界和帧号999回滚测试通过。报告见`validation/`。
- 最终固件使用ESP-IDF 5.4.0编译，已通过COM4烧录并校验；app为893952字节。恢复场景稳定后的关闭/开启上传短测分别301/301、181/181成功，上传组收到20张图片；这些短测不替代正式20秒性能对照。

完整板端数据、耗时口径、局限和早期无效对照说明见[最终集成与实测](../../docs/failure_diagnosis/component_split_20261118/README.md)。

- `firmware/`：当前最终固件、bootloader、分区表、烧录参数和sdkconfig快照；原`releases/20261118/firmware/`保留为历史版本。
- USB图像调试器源码：`tools/ov9281_debugger/`；EXE：`dist/P4ScanOV9281Debugger.exe`，版本v1.0.0004，增加0/1/2尺寸映射。
- 原v1.0.0003源码及EXE备份：`releases/20261118/P4ScanOV9281Debugger_v1.0.0003_backup.zip`。
- 独立STM32 UART/AGV工具源码：`tools/stm32_uart_debugger/`；EXE：`tools/stm32_uart_debugger/release/AGV_3D_Test.exe`。本轮保留原文件。
- STM32接收demo源码及压缩包：`examples/stm32_uart/`、`examples/stm32_uart.7z`；协议见`docs/STM32_UART_PROTOCOL.md`。C/F布局及CRC仍为v6。
- 固件和两款EXE的SHA256见`manifest.json`。

进入`firmware`目录后，可使用IDF 5.4环境下的`python -m esptool --chip esp32p4 --port COM4 --baud 460800 write_flash @flash_args`烧录整套文件；只更新当前同分区板子的app时，地址为`0x10000`。无需擦除NVS。
