# 输出给整机测试20261119

本版用于 ESP32-P4 v1.x 与 OV9281 的整机联调。摄像头以 1280×720 RAW8、50 帧/秒采集。交付镜像是在 P4 rev 1.3 上完成实测的应用，由 ESP-IDF 5.4.0 构建。

## 解码改进

- 每帧重新从 2 像素二值图中寻找候选。结合实心 L 边、内部黑白跳变、白边和外围标记评分，再根据本帧的候选尺寸和得分安排常规搜索与小码补救。
- 极小候选的跳变门槛从 6 次降至 3 次，优先对局部灰度图做两倍插值。这样约 24 像素码体在粗采样丢失部分跳变后仍能进入定位和解码。
- 极小候选的单次搜索上限由 4 ms 调到 8 ms，减少 CSI 采集与解码并行时因提前超时触发的重复搜索。候选仍须通过 ECC200 和原图四边精修。
- 10×10 小码的精修最小边长从 32 像素降至 22 像素，并缩小边缘搜索范围，支持较小码体输出精修角点。

## 板端实测

下表来自标签位置相同、码体约 24 像素的短时静态测试。

| 工况 | 成功／尝试 | 成功输出 |
| --- | ---: | ---: |
| 旧小码优先版，关闭图片上传 | 209/232 | 26.1 帧/秒 |
| 本版，关闭图片上传 | 500/500 | 41.7 帧/秒 |
| 本版，每秒请求 5 张图片 | 438/438 | 36.5 帧/秒 |

历史回归共 1,185 组，保留了基线的 1,090 组精修结果，负样本新增误报 0 组。8 张不同尺寸的样本在 P4 上分别正序和倒序回放，16/16 次解码并精修成功。整机测试可按实际运动和照明工况分别记录成功输出速率、漏检和 UART 姿态数据。详见[现场诊断与实测](../../../docs/failure_diagnosis/throughput_20261119.md)。

## 固件与协议

- 应用镜像为 [p4scan_ov9281.bin](p4scan_ov9281.bin)，994,656 字节。SHA-256 为 `6f5f5601f133b6b03a9ff3fb2d9bad186d8d8cfe96d03703251630f308e437b8`。
- 对已使用本项目分区表的 16 MB Flash 测试板，将应用烧入 `0x10000`。首次装机所需的 bootloader 与分区表及对应烧录地址见 [20261119 基础固件](../README.md#固件与两个ui)。
- STM32 接收端使用 UART v6 的 `C`、`F` 帧及现有示例。参见 [UART 协议](../../../docs/STM32_UART_PROTOCOL.md)和 [STM32 示例](../../../examples/stm32_uart/)。

在本目录使用 IDF 环境烧录应用，`COM4` 替换为实际烧录口。

```powershell
python -m esptool --chip esp32p4 --port COM4 --baud 460800 --before default_reset --after hard_reset write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB 0x10000 p4scan_ov9281.bin
```
