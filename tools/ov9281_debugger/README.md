# P4SCAN OV9281 调试器

Windows x64 可直接运行 `dist/P4ScanOV9281Debugger.exe`。选择 `303A:8001` 的 HS-USB CDC 串口并点击“连接”。软件参考原版 P4ScanDebugger，主画面只显示设备处理过的同帧图像，成功和失败帧都可显示。软件不打开 UVC 实时视频流。

顶部“开启/关闭解码图片上传”按钮与“上传解码帧图片（成功 / 失败）”复选框同步。开启时，软件通过 CDC `@SNAP` 请求下一张处理完成的帧，校验 JPEG 尺寸和 CRC32 后显示。失败帧显示真实图像，不画虚假角点。图像按需采样，不是传感器每一帧。

界面左侧显示连接、统计和较窄的图像预览；右侧信息栏从窗口顶部开始显示双核占用、解码内容和四角 X/Y 坐标，四行角点表格完整可见。顶部不再重复显示每帧实时定位文本，避免小数长度变化导致界面滚动。图像上仅画轮廓和角点，不叠加大号坐标文字。“自动保存收到的图片”默认关闭，勾选后才会把收到的 JPEG 和同帧 JSON 写到所选目录。

右侧顶部的 Core 0、Core 1 占用率来自固件约每秒一次的 `@CPU` 消息，按各核空闲任务运行时间计算。它表示采样区间内各核总占用，包含采集、USB、解码等任务。断开连接或超过 3 秒未收到更新时显示 `—`。

两级跨帧固件的现场开图测试达到约 50 次成功定位/秒，同时每 20 秒收到 54 张按需图片；关图同样约 50 次/秒。Core 0 约 90%、Core 1 约 53%；该值取决于画面和图片上传状态，单帧处理约 23～24 ms。详见 `docs/FRAME_STAGE_PIPELINE.md`。`bench_upload.py` 也统计结果序号重复/缺口、图像校验错误和最大帧龄；`dequeued_fps` 根据应用取帧序号与设备时间计算，不能用于推断 CSI 硬件没有丢帧。

统计显示 CDC 成功结果、扫描轮次及已接收的成功/失败图片数。定位行仅在解码、角点精定位和 100 ms 帧龄检查均通过时发送。`@TIMING` 扫描轮次消息在 USB 拥堵时允许丢弃。关闭图片上传后仍接收定位结果和耗时，主画面改为白底坐标示意。“冻结画面”、最近 30 张、自动保存、导出 JPEG/标注 PNG/JSON、离线样本、角度估计和标定导入沿用参考调试器。默认 23° 视场角只供粗估，实测角度需要导入 OV9281 在 1280×720 下的标定。

“当前收到成功结果”使用最近 5 秒主机接收时间估算，切换图片上传后应等待至少 5 秒再看该数值。固定时段对照可用 `bench_upload.py --port COMx`：默认按开/关/开/关顺序测试，每段先等待 2 秒，再记录 12 秒成功条数、扫描轮次、快照数及解码耗时中位数。2026-11-10 的现场记录见 `docs/upload_benchmark.json`：两轮开图均为 191 条/12秒，两轮关图均为 206 条/12秒；关图没有使设备识码变慢。


从源码构建：

```powershell
cd tools/ov9281_debugger
py -3.11 -m venv .venv
& .venv/Scripts/python.exe -m pip install -r requirements.txt
./build.ps1
```

自动验证可运行 `P4ScanOV9281Debugger.exe --port COMx --auto-connect --smoke-seconds 10 --smoke-output docs/ov9281_ui_smoke`。自动验证时会生成窗口截图、同帧图与 `smoke.json`；COM 号仅是当前枚举值。软件关闭 CDC 时发送 `@DEBUGOFF` 和计时关闭命令。
