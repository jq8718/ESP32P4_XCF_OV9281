# UART 3D AGV Receiver Simulator

独立的 GPIO41/42 UART 调试器，用于模拟 STM32 接收 ESP32-P4 的扫码与姿态数据。不连接 USB CDC、不打开 UVC。v1.0.0021 支持协议 v6、上传模式切换与内参配置命令，切换和配置需要双向接线。

默认串口参数为 921600 baud、8N1。P4 GPIO41 TX 接转接器 RX；转接器 TX 接 P4 GPIO42 RX，双方共地。连接时按复选框请求模式；未收到相符应答会显示未确认，请检查反向接线。新固件默认精简格式（协议 v6），内容直接发送数字字符串，例如 `012345`。帧号以 0～999 循环显示，历史表按接收顺序记录。旧版本行会被拒绝。

“上传完整数据”默认不勾选：精简模式只有帧号、内容、偏航角、码平面垂直距离和沿过道偏移。勾选后上传帧号、内容、四角点、3 个角度和 5 个距离。全部来自 P4，UI 不根据像素重算姿态。新格式以毫度、毫米和 0.1 像素的整数传输，并校验 CRC16；UI 显示转换为度和米。

精简模式上传真实码平面垂直距离，3D 离墙位置与底部离墙数值均使用该量平滑后的结果；精简模式不上传光轴深度。未上传的俯仰、横滚、range、光轴深度和 tx 卡片显示“—”，不把上一笔完整数据当作当前测量。尚未收到有效姿态时显示安装示意。

“相机内参 · 读取 / 下载”可读取设备当前参数、编辑、导入/导出 JSON，以及下载并保存到 P4 Flash。支持平铺内参 JSON 和已有 camera_matrix/dist_coeffs/image_size JSON。填默认值或导入仅修改编辑框，点击下载后才写设备；保存后校对设备 DATA 回读，应答超时不显示成功。标定尺寸固定 1280×720。模式切换只写 RAM，内参配置才写 Flash。

协议、整数比例和可移植 STM32 C 解析器见 [STM32 UART 整数协议](../../docs/STM32_UART_PROTOCOL.md)。整数协议字段、位宽与溢出说明见上链接；旧浮点 CSV 已移除。

右侧 3D 状态图将二维码固定在垂直墙面上，二维码中心高 0.25 m，相机位于 AGV 右侧中点，光心同样高 0.25 m。模型以光心为姿态旋转基点，保持它与二维码中心等高。场景为后右方追车视角，可同时看到红色尾灯和右侧扫码头。车头采用白色灯组、浅色前罩和向上箭头并标注车头，车尾采用双红灯、黑色保险杠和格栅。圆柱轮胎、轮毂和紧固件均为三维面片，随车体变换并按深度绘制；环境、地面阴影与车体分层，避免地板盖住轮组。

墙边标签仅显示平滑后的垂墙距离厘米数值，例如 `19.1 cm`；历史表内容列按六位数宽度显示，不截断原始解码数据。车宽 0.50 m，过道净宽 1.50 m。离墙距离按 `distance_to_plane_m` 显示；新固件用 `along_track_m` 决定车体沿过道的位置，并按 2.4 倍放大场景位移。原始 `tx` 只在参数卡显示，不再被当作过道位置。车体旋转统一应用于外壳、车轮和相机；右侧相机安装方向为图像右侧对应车体向后、图像下方对应向下、光轴指向车体右侧。依据这一固定安装假设，将相机姿态换算为车体旋转（前进 X、左侧 Y、向上 Z）。用户确认 AGV 原地旋转轴经过相机光心，模型与固件均不作相机安装平移补偿。

相机外壳是三维模型，零姿态下其镜头正面与墙面平行。蓝框表示相机在墙面上的视场投影，四点始终共面于墙体；根据默认 OV9281 内参和 1280×720 分辨率计算，视场约 82°×52°。追车虚拟镜头采用独立的 52° 垂直视场，水平视场随视口宽高比变化，不再把屏幕方向的矩形/椭圆当作车体部件。

`yaw_y`、`pitch_x`、`roll_z` 是相机相对二维码的姿态角。三维场景依据理想的右侧水平安装假设转换姿态，没有实测安装外参，也对 TX 做了显示放大，属于姿态示意。角度跳动时应先核对 P0→P3 角点身份顺序、相机内参与图像分辨率是否匹配、画面清晰度及码体检测稳定性。P4根据内容最左边一位 `0`/`1`/`2` 选择30/50/70 mm边长并计算距离，UI直接接收P4结果。错误的边长选择主要影响距离比例，不会直接改变 PnP 姿态角。

八项参数 `yaw_y/pitch_x/roll_z/range_m/optical_depth_m/distance_to_plane_m/tx/along_track_m` 经过时间常数 0.45 秒的指数平滑后进入 3D。显示定时器每 33 ms 更新，滤波按真实时间计算，独立于串口采样率和绘制帧率；三个角度跨越 ±180° 时均沿最短方向平滑。第一笔有效数据直接初始化，重新连接时清空滤波状态。约 0.45 秒达到目标变化的 63%，约 1.35 秒达到 95%。参数卡、原始 UART 行及历史表继续显示原始值；偏航波形按时间对照原始角度和平滑角度。

代码分工：`app.py` 为串口与 UI，`uart_protocol.py` 为整数协议、CRC 和内参校验，`pose_filter.py` 为参数平滑，`scene.py` 为三维场景。运行 `py -3.12 tools/stm32_uart_debugger/validate_ui.py` 可检查滤波、跨角度边界、帧率独立性、原地转向位置稳定性、固定光心高度、相机平面、轮胎触地、完整/精简模式与内参窗口操作，并输出 `validation/scene_revision` 预览图；验证不打开串口。运行 `py -3.12 tools/validate_uart_integer.py` 验证 Python 与 STM32 C 解析器及损坏报文检查。

构建命令：

```powershell
cd tools/stm32_uart_debugger
./build.ps1
```

生成文件为 `tools/stm32_uart_debugger/release/AGV_3D_Test.exe`，版本显示在窗口标题中。该工具源码、构建号和临时构建目录均位于本目录，与 `tools/ov9281_debugger` 分开；原 `P4ScanOV9281Debugger.exe` 与 v1.0.0003 源码不受影响。
