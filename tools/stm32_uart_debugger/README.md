# UART 3D AGV Receiver Simulator

独立的 GPIO41/42 UART 接收模拟器，用于模拟 STM32 接收 ESP32-P4 的扫码与姿态数据。不连接 USB CDC、不打开 UVC，也不会向串口写入数据。

默认串口参数为 921600 baud、8N1。选择 USB-UART 转接器连接的 COM 口：P4 GPIO41 TX 接转接器 RX，双方共地。设备每行数据解析为内容、8 个角点坐标、帧号及 `yaw_y`、`pitch_x`、`roll_z`、`range_m`、`optical_depth_m`、`distance_to_plane_m`、`tx`。坐标字段单位是 0.1 像素。

右侧 3D 状态图将二维码固定在垂直墙面上，二维码中心高 0.25 m，相机位于 AGV 右侧中点，光心同样高 0.25 m。模型以光心为姿态旋转基点，保持它与二维码中心等高。场景为后右方追车视角，可同时看到红色尾灯和右侧扫码头。车头采用白色灯组、浅色前罩和向前箭头，车尾采用双红灯、黑色保险杠和格栅，画面带车头/车尾标注。圆柱轮胎、轮毂和紧固件均为三维面片，随车体变换并按深度绘制；环境、地面阴影与车体分层，避免地板盖住轮组。

车宽 0.50 m，过道净宽 1.50 m。离墙距离按 `distance_to_plane_m` 显示，`tx` 保持现场已确认的方向、按 2.4 倍放大场景位移，原始参数卡仍显示串口原值。车体旋转统一应用于外壳、车轮和相机；右侧相机安装方向为图像右侧对应车体向后、图像下方对应向下、光轴指向车体右侧。依据这一固定安装假设，将相机姿态换算为车体旋转（前进 X、左侧 Y、向上 Z）。

相机外壳是三维模型，零姿态下其镜头正面与墙面平行。蓝框表示相机在墙面上的视场投影，四点始终共面于墙体；根据默认 OV9281 内参和 1280×720 分辨率计算，视场约 82°×52°。追车虚拟镜头采用独立的 52° 垂直视场，水平视场随视口宽高比变化，不再把屏幕方向的矩形/椭圆当作车体部件。

`yaw_y`、`pitch_x`、`roll_z` 是相机相对二维码的姿态角。三维场景依据理想的右侧水平安装假设转换姿态，没有实测安装外参，也对 TX 做了显示放大，属于姿态示意。角度跳动时应先核对 P0→P3 角点身份顺序、相机内参与图像分辨率是否匹配、画面清晰度及码体检测稳定性。错误的 30/50 mm 边长选择主要影响距离比例，不会直接改变 PnP 姿态角。

七项参数 `yaw_y/pitch_x/roll_z/range_m/optical_depth_m/distance_to_plane_m/tx` 全部经过时间常数 0.45 秒的指数平滑后进入 3D。显示定时器每 33 ms 更新，滤波按真实时间计算，独立于串口采样率和绘制帧率；三个角度跨越 ±180° 时均沿最短方向平滑。第一笔有效数据直接初始化，重新连接时清空滤波状态。约 0.45 秒达到目标变化的 63%，约 1.35 秒达到 95%。参数卡、原始 UART 行及历史表继续显示原始值；偏航波形按时间对照原始角度和平滑角度。

代码分工：`app.py` 为串口与 UI，`pose_filter.py` 为七项平滑，`scene.py` 为三维场景。运行 `py -3.12 tools/stm32_uart_debugger/validate_ui.py` 可检查七项滤波、跨角度边界、帧率独立性、固定光心高度、相机平面和轮胎触地，并输出 `validation/scene_revision` 预览图；验证不打开串口。

构建命令：

```powershell
cd tools/stm32_uart_debugger
./build.ps1
```

生成文件为 `tools/stm32_uart_debugger/release/AGV_3D_Test.exe`，版本显示在窗口标题中。该工具源码、构建号和临时构建目录均位于本目录，与 `tools/ov9281_debugger` 分开；原 `P4ScanOV9281Debugger.exe` 与 v1.0.0003 源码不受影响。
